# 本地输入与日常节奏

- 版本：v0.2
- 日期：2026-10-18
- 适用范围：本地单人使用；自动采集优先使用公开数据、官方接口和平台导出，手动导入永远保留为兜底

## 1. 目标

把个人内容生产从“周末集中硬做”改成“系统先自动准备输入，人每天早上做判断，每天推进一个生产阶段”。对标账号可以后续慢慢导入，但账号、采集运行、快照和分流规则先固定下来。

## 2. 四层输入

### 2.0 自动采集

账号进入注册表后，系统按配置在早上处理前运行：

```text
source adapter → raw snapshot → collection_run → normalize → dedupe → Inbox / 素材候选
```

第一阶段不要求所有平台全自动。可以一个账号用公开数据或平台导出跑通定时闭环，其他账号先用浏览器辅助或手动导入。每次运行必须留下状态：成功、部分成功、失败、失败原因、下一步人工动作。

### 2.1 快速收集

看到好内容时只要求两个字段：

1. 链接。
2. 一句话说明为什么值得看。

其余字段可以后补。快速收集的目标是降低记录成本，不是当场完成判断。

### 2.2 结构化导入

统一使用 `data/import-template.json`，包含四类对象：

1. `sources`：对标账号和信息源。
2. `signals`：具体内容信号。
3. `materials`：观点、热评、金句、案例、数据和反例。
4. `topics`：已经想做的选题。

第一版以手动填写和 JSON 导入为主。链接相同的记录视为重复项，导入时保留最早记录并合并后续备注。

### 2.3 早上分流

默认早上处理，建议 09:00 开始，采集任务建议 08:30-08:50 完成，具体时间可在设置中调整。每次最多处理 10 条，超过的部分保留在 Inbox，不为了清空而降低判断质量。

## 3. 早上 45 分钟流程

| 时间 | 动作 | 输出 |
|---|---|---|
| 0-5 分钟 | 打开今日页，确认今天唯一焦点 | 今天推进哪一条 |
| 5-20 分钟 | 处理 Inbox，给每条信息一个去向 | 丢弃 / 观察 / 拆解 / 入素材库 / 入选题池 / 直接生产 |
| 20-40 分钟 | 推进一个生产阶段 | 大纲、素材包、稿子版本、录制清单或发布包 |
| 40-45 分钟 | 收尾 | 下一步动作、预计耗时、摩擦点 |

收尾时必须写清楚下一次打开工作台时的第一个动作，例如“核对三个证据链接”或“把第二版口播稿导入生产台”。

## 4. 口播视频生产块

第一阶段不要求一天内完成所有环节，而是把一个视频拆成可暂停、可恢复的生产块：

| 阶段 | 输出 | 建议时长 |
|---|---|---|
| 选题确认 | 一句话观点、目标读者、最小版本 | 20 分钟 |
| 结构大纲 | 开头、论证、证据、结尾 | 20 分钟 |
| 外部写稿 | 大纲和素材包交给 Gemini / Claude Opus | 40 分钟 |
| 稿件取舍 | 导入终稿，记录人工修改 | 40 分钟 |
| 证据核对 | 逐条核对来源和引用 | 30 分钟 |
| 录制准备 | 口播稿、提词要点、录制清单 | 20 分钟 |
| 录制 | 样片或完整口播 | 30-60 分钟 |
| 剪辑粗版 | 剪口误、加字幕、检查节奏 | 60 分钟 |
| 发布包 | 标题、描述、话题、公众号文稿 | 40 分钟 |
| 发布台账 | 抖音、小红书、公众号状态；X 发或跳过 | 30 分钟 |

第一次跑通时可以分为 3-5 天完成。目标是让前三个视频从“一个周末”逐步压缩到一个可控工作日；先保证质量和可持续，再追求速度。

## 5. 日常出摊分层

不建议把“每天一个内容”直接定义为每天一条完整口播视频。第一版分三层：

| 层级 | 内容 | 用途 |
|---|---|---|
| A：完整作品 | 口播视频 + 公众号文稿 | 质量和体系沉淀 |
| B：轻内容 | 当前素材整理、短图文、观点笔记 | 保持公开输出和思考频率 |
| C：内部产出 | 拆解报告、大纲、素材包、稿子版本 | 支撑 A 和 B，不一定公开 |

默认节奏：每天至少完成一个 C，争取产出 B，A 按流水线推进。等模板和素材库稳定后，再评估是否能提高 A 的频率。

## 6. 摩擦记录

每天收尾时只记录一条真实摩擦：

- 卡在哪一步。
- 实际用了多久。
- 下次能不能模板化。
- 是否值得自动化。

产品功能自动化候选只从这张摩擦记录里选，不凭想象提前开发。采集自动化的优先级同时看两个输入：账号是否已长期监控、该平台人工采集是否高频耗时。
