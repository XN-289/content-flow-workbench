# 工作台体验调研：轻量吸收边界

更新时间：2026-10-20 11:55

## 结论

当前工作台的信息架构方向是对的：四个大类 tab 解决了此前所有模块堆在一个页面的问题。但只做分层还不够，个人创作者每天打开工作台时最需要的是“现在做什么、卡在哪、离发布还差多少”。因此本轮吸收行动队列、阶段漏斗和平台队列模式，而不是继续增加录入表单。

## 参考项目

以下数据来自 2026-10-20 GitHub API 只读查询：

- `gitroomhq/postiz-app`：约 37,426 stars，社媒排期与发布平台。
- `inovector/mixpost`：约 3,834 stars，自托管社媒内容排期与发布管理。
- `langchain-ai/social-media-agent`：约 2,920 stars，从信息源生成内容并保留人工审核。

## 吸收的模式

1. Postiz / Mixpost 的队列视角：总览输出「现在 / 接着 / 稍后」的行动顺序，发布台账按抖音、小红书、公众号、X 显示未完成、已发布、被阻塞和完成率。
2. Mixpost 的平台差异意识：一个作品可以按平台拆成发布记录，后续继续演进为平台文案版本，而不是把一条内容视为完全相同的平台投放。
3. LangChain social-media-agent 的人工关卡：Agent 和自动抽取只生成候选，进入选题、生产、发布仍要经过服务端状态机和用户判断。

## 不吸收的模式

- 不做团队协作、多租户、权限系统和在线 SaaS。
- 不直接接入平台发布 API，不保存平台登录态，不做无人值守自动发布。
- 不引入重型数据库、独立队列、Docker 编排或多人审批流。
- 不用二级 tab 破坏当前四个大类 tab 的手感；大类内部用连续模块和锚点解决定位。

## 本轮落地

- `总览`：新增每日行动优先队列和 3 条作品目标进度。
- `信息流`：新增进料、Inbox、素材沉淀的节奏条。
- `工作流`：新增选题、提纲 / 草稿、制作 / 待审、待发、发布 / 复盘阶段漏斗。
- `工作流复盘`：新增近 3 天摩擦摘要，把工作台体验验收从口头记忆变成记录数、耗时和可模板化点。
- `发布台账`：新增平台级队列，未完成记录排在已发布之前。
- 修复 hash 路由不重渲染的问题，浏览器返回 / 前进可正常切换大类。
- 修复系统页在 390px 视口的横向溢出；桌面和移动端四个大类均检查通过。

## 验收边界

结构回归只能证明链路和布局没有破坏，不能证明日常体验已经好。下一次体验验收应连续使用三个真实工作日：每天早上只从总览行动队列开始，记录是否还需要手工翻找入口、判断下一步和补平台发布记录。
