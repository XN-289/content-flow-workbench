## 2. 三条视频分别解决了什么问题

### 2.1 主工作台视频：定义系统边界

主视频展示的不是普通内容看板，而是一个个人内容操作系统：

- 信息来源：老师、对标账号、Newsletter、Clippings、Bookmarks、原始来源。
- 信号处理：用相对中位数识别异常好内容，而不是只看绝对点赞数。
- 内容拆解：生成报告，分析钩子、承诺、论证、证据、案例、结尾。
- 选题与排期：进入选题池，可提前安排一个月。
- 生产辅助：语音输入、一键生成框架、开头、结构、证据、截图、插图、动效。
- 发布与监测：剪辑、打包、发布、回收数据。
- Agent 分工：Wendy 面向老板 / 战略，Anna 面向内容编辑。

作者反复强调的原则是：功能来自真实使用摩擦；工作台要把方法论编码成可迁移流程；交给别人不改流程也能复现类似结果。

### 2.2 1:15 补充演示：最适合我们复用的原型

这条视频把一个具体事件跑完整：

> 对标博主今天爆了一条，怎么变成你 7 个平台的视频和文章？

画面顶部持续显示四个核心计数：

1. 这条线上用到的功能数。
2. 自动步骤数。
3. 你动手数。
4. 平台完成度，如 `0/7` 到 `7/7`。

最终画面展示为：

- 211 个功能上线。
- 这条线用到 116 个功能。
- 30 个自动步骤。
- 16 个人工动作。
- 完成 7 个平台。

这些是作者画面展示的数字，不作为我们项目目标。真正值得借鉴的是这四个计数器：系统复杂度、自动化程度、人工投入和交付进度随时可见。

### 2.3 策略视频：解释为什么工作台这样设计

策略视频的核心观点可以概括为：

1. 自媒体从增量市场进入存量市场，已有粉丝和执行能力的重要性下降。
2. AI 让执行变便宜，信任、品味和判断变贵。
3. 内容业务可拆成前端、中端、后端：前端负责触达，中端负责转化、运营和交付，后端负责产品与商业闭环。
4. 内容本身不只是作品，而是触达、信任和产品销售之间的一条链路。
5. 优化时不能同时优化所有指标，要先知道每一步的转化，再优化最上游的触达或最关键的卡点。

这对我们的启示：工作台不能只管理“写稿 / 剪视频”，还要管理为什么选题、为什么相信、为什么转化、为什么复购。

## 3. Park 工作台的稳定结构

### 3.1 今日页

可见信息：

- 今天拍哪条。
- 明天先干什么。
- 出摊 / 连续天数。
- 全网粉丝和每天触达。
- 当前焦点内容。
- 一行字快速选题。

设计要点：今日页不是首页装饰，而是当天唯一决策入口；指标极度收敛，画面里“今天”只盯出摊、粉丝、触达等少数线；每天结束根据数据决定下一条内容。

### 3.2 信息输入与对标监控

画面展示的机制：

- 每天固定时间，如 9:30，自动抓取关注对标号的更新。
- 只读每个号最新一页，减少请求和风控。
- 过滤新号，避免误判。
- 以作者自己的点赞中位数为基准。
- 当内容互动达到平时的 1.5 倍或 2.5 倍以上，自动排到更上面。
- 提供“去看”和“看过”状态，避免重复处理。

这是最值得复用的算法思想：异常值是相对数，不是绝对数。

### 3.3 收件箱与信号分流

可见路径：

- 对标视频进入进项。
- X 收藏、AI 日报、原始输出存进 Obsidian。
- 跟 Anna 说一句话，可以存成“流量视频”。
- 刷到想复刻的内容，写入“接下来要拍”。
- GitHub、网站、Obsidian 是另一条素材线。

设计要点：Inbox 不是垃圾桶，而是按出口分流；每条信号必须有明确去向：丢弃、观察、拆解、进选题、直接生产；素材线与对标线分开，避免把灵感和可执行选题混在一起。

### 3.4 拆解报告

可见动作：

1. 点“拆解”。
2. 下载原视频。
3. Whisper 转写。
4. Claude 判断。
5. 生成拆解报告。
6. 报告展示“他是怎么做的”。
7. 用户点“做这个”。

可见选择：完全复刻、借他的结构、进入选题池、建成系列一集一集拍。

设计要点：拆解报告必须回答“可复用什么”，不是只做摘要；“做这个”是信号变成选题的关键按钮；复刻与借鉴必须显式选择，避免无意识搬运。

### 3.5 选题池与阶段

画面展示的阶段：

```text
选题 → 提纲 → 录制 → 剪辑 → 待发
```

其他能力：焦点卡、阶段自动推断、系列选题、设为焦点、今天页一行字决定是否推进。

设计要点：阶段是生产流水线状态，不是随便打标签；同一时间只能有一个焦点，减少并行带来的拖延；系列化能把一次拆解的收益放大。

### 3.6 内容生产与质量控制

画面可见能力：

- 一键生成骨架。
- Claude Opus 生成口播稿。
- 三点 QA。
- 按论点找证据：新闻、数据、原推。
- 逐字核对。
- 五个开头候选。
- 每行口播的时间线。
- 证据放进视频截图卡和文章配图。
- 录口播，照提纲讲。
- 剪映粗剪，剪口误。
- 导出 `mp4 + SRT`。
- Whisper large-v3-turbo 做字幕对齐。
- Remotion 做动效和 Hook。
- 10 秒样片先审，批准后才渲染整条。
- 整条渲染后跑质检。
- 机器检查包含禁用词、字号、遮挡等。

最重要的设计不是自动化，而是人工关卡：证据要人工核对；样片不批准，不渲染整条；最终成片要人工终审；插图、标题、发布动作通常由人确认后才执行。

这解决了 AI 生产最危险的问题：生成很便宜，但错误、幻觉和品味失控也很便宜。

### 3.7 打包与多平台适配

画面展示：

- 标题是用户唯一必须填的字段。
- Claude 生成 6-10 个标题候选。
- 描述、话题、平台限制自动处理。
- 生成 `copy.json`。
- 五个平台文案一次填。
- 16:9 自动垫边。
- 中文智能断行。
- AI 双版封面。
- Codex / image-gen 生成封面。
- 公众号排版、小红书图文、X 图文文章。

设计要点：平台差异被建模成适配层，而不是让用户每次重新改格式；文案和素材从同一内容源派生；打包结果是可检查的结构化产物，而不是散落的文件。

### 3.8 发布与补发

画面展示的策略：

- 先发抖音，作者手动上传。
- 点“发了”，系统记录 `published_video_id`。
- 其他平台进入补发工作台。
- YouTube 自动上传，审核后公开。
- B 站自动投稿。
- X 图文直接发。
- 公众号进草稿箱，用户手动群发。
- 视频号准备好文件夹，用户上传。
- 小红书准备好文件夹，用户上传。
- 没发出去时给登录按钮，登录后继续。
- 发齐的内容折叠。
- 出错时闭环记录：为什么错、做什么、自己再试还是系统处理。

设计要点：不追求所有平台全自动；风险高、登录复杂、审核不可控的平台保留人工上传；发布状态按平台逐列追踪；失败不是异常，而是工作流的一部分，必须有原因和下一步。

### 3.9 数据回流与复盘

画面展示：

- 数据每天自动同步。
- 已发出概览。
- 触达总览。
- X 回复计数。
- 私信记录。
- 每天触达曲线。
- 全网粉丝曲线。
- 出摊 / 连续天数。
- 一天一条新视频，工作台记分。

复盘不是只看播放量，而是回答：这条内容触达了多少人；哪类结构带来互动；哪个平台值得继续分发；下一条应该完全复刻、借结构，还是停止这类选题。

## 4. Agent 与 Skills 的组织方式

Park 工作台有两个明显的 Agent：

- Wendy：战略 / 老板视角，晚上排短帖，早上一键确认发送。
- Anna：内容编辑视角，能看到当前屏幕页面，负责信号、拆解和内容推进。

Skills 的组织原则：

> 每个 skill 挂在使用它的那一步，而不是堆在一个大菜单里。

例如：拆解步骤挂 Whisper 转写和 Claude 判断；骨架步骤挂 Claude Opus 和三点 QA；字幕步骤挂 Whisper；动效步骤挂 Remotion；质检步骤挂 `check.py`；封面步骤挂 image-gen；发布步骤挂平台适配。

这是我们把 AI 工具接入个人工作台时最应该保留的约束：AI 能力必须依附于具体流程节点，否则很快变成聊天玩具。

## 5. Park 原型最值得吸收的十条原则

1. 事件驱动：从一个具体信号启动整条生产链。
2. 相对异常：用作者自身中位数判断爆没爆。
3. 明确去向：每条信息必须被丢弃、观察、拆解、入池或生产。
4. 拆解产出行动：报告必须能变成“做这个”。
5. 阶段显性化：选题、提纲、录制、剪辑、待发。
6. 自动化计数：功能数、自动步骤、人工动作、平台进度可见。
7. 人工关卡：证据、样片、终审、发布前确认不能省。
8. 技能挂节点：AI 能力出现在具体流程步骤上。
9. 平台适配：一次生产，多平台派生，但不同风险不同自动化等级。
10. 数据回流：发布不是结束，数据决定下一条。

## 6. 我们不直接照搬的部分

第一版不做：

- 211 或 240 个功能。
- 259 个接口。
- 7 个平台自动发布。
- Remotion 动效流水线。
- Whisper large-v3-turbo 本地转写。
- 复杂 Agent 双人格体系。
- 全自动公众号、B 站、YouTube 上传。
- 自动生成完整成片。

原因：我们还没有验证自己的日常使用频率；自动化之前必须先手动跑顺流程；接口、登录、风控和平台审核会吞掉开发时间；第一阶段的核心风险是“不用”，不是“不够自动”。

## 7. 我们的第一版原型骨架

### 7.1 今日页

回答四个问题：

1. 今天推进哪一条？
2. 当前阶段是什么？
3. 今天必须人工确认什么？
4. 昨天发布内容表现如何？

首屏指标先只保留：连续出摊天数、待处理信号数、生产中作品数、待发布作品数。

### 7.2 对标监控 Inbox

字段：来源作者、平台、内容链接、发布时间、作者中位数基准、当前互动相对倍数、信号等级、看过状态、去向。

第一版不自动抓取也可以，先手动录入，但必须保留相对倍数字段。

### 7.3 拆解报告

固定模板：

- 现象与数据。
- 目标人群。
- 开头钩子。
- 核心承诺。
- 论证结构。
- 证据类型。
- 案例组织。
- 情绪和语气。
- 结尾动作。
- 可复用结构。
- 不适合我的地方。
- 建议动作：完全复刻 / 借结构 / 只保存 / 丢弃。

### 7.4 选题池

第一版状态：

```text
选题 → 提纲 → 草稿 → 制作 → 待审 → 待发 → 已发 → 已复盘
```

### 7.5 生产台

每条内容固定七个检查项：核心观点、目标读者、开头钩子、结构大纲、证据案例、配图素材、发布包。

人工关卡：证据核对、开头确认、样片或草稿确认、终审。

### 7.6 发布台账

一行一个平台：

| 字段 | 说明 |
|---|---|
| 平台 | X、公众号、小红书、抖音、视频号等 |
| 状态 | 未准备、待人工、已发、失败、跳过 |
| 链接 | 发布后的链接 |
| 发布时间 | 实际时间 |
| 失败原因 | 登录、审核、格式、素材、放弃 |
| 下一步 | 重试、人工上传、放弃 |

第一版只做台账，不做自动上传。

### 7.7 复盘页

每条内容记录：曝光 / 触达、互动、收藏、评论核心反馈、假设、结果、保留、砍掉、下一条改法。

## 8. 与既有 PLAN 的衔接

原 `PLAN.md` 的主流程仍然成立，但从现在开始要按 Park 原型补齐三个点：

1. 今日页必须是第一屏，而不是功能首页。
2. 对标信号要用“相对中位数倍数”排序。
3. 生产、打包、发布、复盘要拆成显性阶段和人工关卡。

项目路线调整为：

1. M0：确认 Park 原型分析和项目边界。
2. M1：录入真实信息源和 10 条对标信号。
3. M2：跑 3 次手动拆解，验证拆解模板。
4. M3：做本地 MVP 今日页 + Inbox + 选题池。
5. M4：完成一条内容的完整生产、发布台账和复盘。
6. M5：连续 7 天使用。
7. M6：只把最高频摩擦自动化。
