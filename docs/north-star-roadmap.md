# North Star Roadmap · Park-style Content Studio

- 版本：v0.2
- 日期：2026-10-18
- 最终对标：用户最初展示的 Park / `@xparkzz` Content Studio 演示
- 结论状态：自动采集主线已确认，阶段细节待用户确认

## 1. North Star 一句话

一个本地优先的个人内容操作系统：对标账号注册进来后，系统能每天自动检查更新、保存快照、识别异常信号，并把异常信号推进成拆解报告、选题、证据包、口播稿、动画视频、多平台发布包和复盘记录，全程显示自动步骤、人工动作和平台进度。

这不是一个普通看板，而是一条事件驱动的内容生产线。

## 2. 最终形态的完整链路

```text
对标账号注册表
  ↓
每日自动采集：定时检查、原始快照、运行日志、失败重试
  ↓
对标信号
  ↓
相对异常判断：作者中位数 / 1.5x / 2.5x
  ↓
Inbox 分流：丢弃 / 观察 / 拆解 / 入素材库 / 入选题池 / 直接生产
  ↓
拆解报告：钩子、承诺、论证、证据、结构、可复用点
  ↓
“做这个”决策：完全复刻 / 借结构 / 只保存 / 丢弃
  ↓
选题池：目标读者、核心观点、最小可发布版本
  ↓
证据包：原文、数据、截图、来源、可信度、引用边界
  ↓
口播稿：骨架、开头候选、论证、结尾、人工取舍
  ↓
分镜与时间线：每句话对应画面、字幕、证据卡和动效
  ↓
动画渲染：Hook、重点词、截图卡、数据卡、案例卡、节奏变化
  ↓
样片关卡：先审 10 秒，再渲染整片
  ↓
机器质检：字幕、字号、遮挡、禁用词、来源、画面空帧
  ↓
多平台打包：视频、公众号文稿、小红书文案、封面、标题候选
  ↓
发布与补发：平台台账、失败原因、下一步动作
  ↓
数据回流：触达、互动、评论、粉丝、连续出摊
  ↓
下一条决策：复刻、借结构、停止或系列化
```

## 3. 动画生产线的样子

最终动画系统不是“给视频加特效”，而是把内容和时间线结构化后自动生成可审的视频画面。

### 3.1 内容解析

口播稿先被拆成句子和语义块，每个块至少包含：

- 口播文本
- 开始和结束时间
- 语义角色：Hook、问题、判断、论证、证据、案例、转折、总结、行动
- 重点词
- 情绪强度
- 关联证据或素材

### 3.2 画面选择

系统根据语义块选择画面组件：

| 内容类型 | 画面组件 |
|---|---|
| 核心判断 | 大字卡、重点词高亮 |
| 证据 | 截图卡、引用卡、来源角标 |
| 数据 | 数字滚动、对比条、趋势线 |
| 案例 | 分屏、步骤卡、时间线 |
| 反差或转折 | 左右对比、遮罩揭示、镜头推近 |
| 总结 | 清单卡、结论卡、行动按钮 |

### 3.3 动效模板

动效不是随机出现，而是由模板和语义触发：

- 重点词浮现、下划线、放大。
- 证据截图从后台页面截图中裁切进入。
- 数据从 0 滚动到目标值。
- 论证步骤逐条出现。
- 反例和正例左右分屏。
- Hook 使用更强节奏和更短镜头。
- 总结阶段降低动效密度，突出行动指令。

### 3.4 渲染与质检

目标流程：

1. 生成结构化 storyboard JSON。
2. 按时间线生成静态预览。
3. 先渲染 10 秒样片。
4. 人工确认 Hook、节奏、字体、颜色和信息密度。
5. 再渲染整片。
6. 机器质检字幕、遮挡、字号、空帧、禁用词、来源缺失。
7. 人工终审后才进入发布包。

技术候选是 Remotion 或同类浏览器渲染方案，但先不绑定实现。关键是 storyboard、时间线、素材和质检规则必须结构化，否则换任何渲染器都会重复手工劳动。

## 4. 自动采集生产线

自动采集不是后期附加功能，而是 North Star 的入口能力。目标形态是：

```text
账号注册
  ↓
定时检查：按账号频率执行，默认每天早上前完成
  ↓
source adapter：公开页面 / 官方接口 / 平台导出 / 浏览器辅助 / 手动导入
  ↓
原始快照：保留当时看到的页面和数据口径
  ↓
规范化：内容、作者、发布时间、互动数、评论线索
  ↓
去重：链接、内容 ID、标题、发布时间四层判断
  ↓
异常计算：作者中位数、相对倍数、更新间隔变化
  ↓
Inbox 候选与素材候选
  ↓
人工分流：丢弃 / 观察 / 拆解 / 入素材库 / 入选题池 / 直接生产
```

采集自动化分级：

| 等级 | 方式 | 用途 |
|---|---|---|
| L0 | 手动链接和备注 | 永久兜底 |
| L1 | 浏览器辅助、复制粘贴、文件导入 | 登录和风控强的平台 |
| L2 | 公开页面、RSS、官方接口、平台导出 | 优先生产方案 |
| L3 | 本机定时任务、队列、失败告警 | 无人值守日常运行 |
| R | 逆向研究 | 独立实验室，不进入生产依赖 |

所有平台 adapter 必须遵守同一契约：输入账号配置，输出原始快照和结构化候选；不能输出时写清失败原因、重试次数和需要的人工动作。小豆芽的界面、数据口径和接口研究可以放入 R 级实验室，生产链路先使用公开数据、官方导出或人工导入。

## 5. 最终 UI 的四个显性计数

参考 Park 的演示，每条生产线顶部持续显示：

1. 本条链路用到的功能数。
2. 自动步骤数。
3. 人工动作数。
4. 平台完成度，如 `0/4 → 4/4`。

我们不追求复刻 211 个功能或 116 个功能的数字，而是保留这个设计原则：复杂度、自动化程度、人工投入和交付进度必须可见。

## 6. 阶段路线

### Phase 0：现在，方法与数据基线

目标：先把信息、素材、选题、生产状态和发布台账变成结构化对象。

- 已有 Park 原型分析。
- 已有 40 天三口播目标。
- 已有本地导入模板和早上处理节奏。
- 待做：录入真实信号、素材和三个主题。

### Phase 1：0-40 天，本地 MVP 与三条口播

目标：完成本地单人闭环，不追求自动渲染。

- 今日页、Inbox、素材热评库、拆解、选题池、生产检查、发布台账、复盘。
- 账号注册表、采集运行表、原始快照表和 source adapter 接口。
- 至少一个信息源完成定时或半自动采集闭环，其他平台保留手动导入兜底。
- 三条口播视频 + 公众号文稿。
- 视频画面可以先靠剪映或简单字幕卡完成。

验收：一条内容从账号检查或手动导入开始，到发布复盘都能在本地系统中追踪；采集失败时能看到原因和下一步。

### Phase 2：41-80 天，生产结构化

目标：让每个作品都有可复用数据和模板。

- 固化拆解模板。
- 固定口播稿结构。
- 建立证据包和来源引用规范。
- 建立 storyboard JSON 雏形。
- 沉淀标题候选、开头候选和平台文案模板。

验收：第二阶段生产一条视频时，不需要从空白文件开始。

### Phase 3：81-140 天，动画工作室

目标：从结构化稿子生成可审动画。

- 分句和时间线。
- 语义块和画面组件映射。
- 重点词高亮、证据卡、数据卡、案例卡模板。
- 10 秒样片渲染。
- 整片渲染和机器质检。

验收：一条 3-5 分钟口播稿能生成结构化 storyboard，并渲染出通过人工终审的样片或整片。

### Phase 4：141-220 天，多平台打包与半自动发布

目标：一次内容生产派生多个平台版本。

- 视频规格适配：竖屏、横屏、封面。
- 公众号文稿、小红书图文和抖音描述自动派生。
- 标题候选和人工确认。
- 发布台账与补发队列。
- 低风险平台尝试半自动，风险平台保留人工。

验收：一次生产输出完整发布包，平台状态逐列可追踪。

### Phase 5：221-365 天，数据回流与个人 Agent

目标：让数据和经验反过来驱动下一条。

- 数据每日回流。
- 高价值评论进素材库。
- 结构表现和选题表现分析。
- Agent 只挂在具体流程节点。
- 自动化候选来自摩擦记录，而不是想象。

验收：系统能回答哪类结构、选题和平台值得继续投入。

## 7. 从现在开始必须保护的数据契约

即使第一版不做完整自动化和动画，也不能把数据记坏：

1. 账号必须有平台、链接、检查频率、采集方式、数据边界和运行状态。
2. 采集运行必须有开始结束时间、结果数量、状态、失败原因和人工下一步。
3. 原始快照必须能追溯到来源和采集时间。
4. 素材必须有来源、原文摘录、可用方向和引用边界。
5. 证据必须有来源、链接、可信度和核对状态。
6. 选题必须关联信号、素材、目标读者和核心观点。
7. 口播稿必须保留版本、使用工具、输入摘要和人工取舍。
8. 视频必须能拆成句、时间线和语义块。
9. 发布必须按平台记录状态、链接、失败原因和下一步。
10. 复盘必须回流到素材库和下一条决策。

这些字段是通向 North Star 的轨道。第一版界面可以简单，但数据结构不能只做成一个笔记字段。
