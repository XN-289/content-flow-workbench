# 工作台 UI 设计原则与验收门槛

更新时间：2026-10-20 14:11

这份文档不是风格说明，而是本项目 UI 改动的验收门槛。以后任何界面改动先过这里的流程和清单；不过就不算完成，也不能提交。

## 产品定位

Content Flow Workbench 是单人使用的本地内容生产工作台。它不是营销官网，也不是多人 SaaS 后台：界面目标是让一个创作者在早上快速判断“现在处理什么、卡在哪里、离发布还差多少”，并把高价值信息沉淀成可复用素材。

## 一级原则

1. **先工作流，后界面。** 任何改动先说明服务于哪个真实动作：进料、Inbox 清零、素材沉淀、选题、写稿、发布、复盘，还是系统恢复。不能只因为某个组件好看就加入。
2. **信息架构固定为四个大类 tab：总览、信息流、工作流、系统。** 大类内部用连续模块和锚点组织，不恢复二级 tab，也不把所有模块重新堆回一个页面。
3. **行动优先。** 默认视图要输出下一步动作和当前阻塞；表单和配置只在对应对象旁边出现。用户不应该为了判断下一步而翻找页面。
4. **隐式状态必须有显式控件。** 明暗模式、自动化暂停 / 恢复、筛选、排序、运行状态、同步开关，只要影响用户看到的内容或系统行为，就必须能被看到、切换并显示当前值。
5. **用户选择必须可恢复。** 主题、筛选、排序、折叠状态等本地偏好应有明确持久化策略；至少主题必须保存在 `localStorage`，刷新后保持一致。
6. **操作入口靠近对象。** 编辑在卡片附近，补采在账号附近，导入结果靠近任务，恢复和备份在一起。孤立设置页只承载真正全局的配置。
7. **状态永远诚实。** 加载、失败、空数据、待人工、禁用、阻塞、完成分别可读；不能让自动化失败看起来像成功，也不能用空白区域代替说明和下一步动作。
8. **质量和安全一样验收。** UI 改动必须同时通过布局、键盘、焦点、触控、主题和文案检查；业务回归通过不等于界面合格。

## 视觉语言

- 基调：Apple 式克制的工具界面。中性表面、清晰层级、少量阴影，不做装饰性渐变、玻璃堆叠、营销 hero 或大图背景。
- 主色：保留一个主行动色，当前为系统蓝；危险、成功、警示只用于对应状态，不做彩色装饰。
- 面板：内容块使用 8px 圆角、白色 / 深色表面、细分边界和低强度阴影；卡片内部不再嵌卡片。
- 排版：界面文字保持紧凑清晰，不用营销页大字号；中文正文、辅助说明、按钮文字都要有足够对比。
- 间距：以 8pt 节奏组织组件、模块和页面间距，不混入随机间距。
- 控件：模式切换优先使用分段控件，二元状态使用开关，动作使用按钮，筛选使用胶囊控件；图标必须配合可见文字或可访问名称。
- 布局密度：这是高频工作台，优先可扫描和批量处理；留白服务于分组，不追求空旷。

## 明暗模式规则

- 顶栏提供显式三态控件：自动、浅色、深色；不能只依赖系统偏好。
- `auto` 跟随系统；`light` 和 `dark` 是用户显式覆盖，刷新后仍保持。
- 颜色通过语义 token 映射，不在每个组件里散落双套十六进制值。
- 两种主题分别检查：正文对比不低于 4.5:1，边框、分割线、焦点、禁用、错误和成功状态都可见。
- 深色不是把浅色变黑：表面层级、阴影、透明度和边框要重新定义，保证面板浮起、文字不灰掉。

## 交互与可访问性

- 所有交互控件可用键盘操作；`Tab` 顺序符合视觉顺序，焦点可见且不被吸顶栏或浮层遮挡。
- 图标按钮必须有可访问名称；图标旁已有文字时图标作装饰处理。
- 鼠标悬停不能是唯一信息来源；颜色不能是唯一状态提示。
- 触控目标不小于 44px；桌面点击区域也保持稳定，不在 hover 或按压时引起布局跳动。
- 表单要有可见标签、必要提示和靠近字段的错误信息；不能只用 placeholder 代替标签。
- 表单失败保留已输入内容和字段错误；影响全局的错误要能被辅助技术感知。
- 动画只表达状态或空间关系，时长克制，并支持减少动态效果。

## 响应式门槛

- 手机基准宽度 390px：无横向溢出，无文字重叠，无固定栏遮挡内容。
- 桌面基准宽度 1440px：四个大类 tab 全部可见，内容密度合理，不出现无意义超宽长文本。
- 移动端导航和工具栏允许换行或收缩，但当前页面和当前状态必须清楚。
- 列表、表格、任务卡片在窄屏优先垂直堆叠；隐藏内容必须有明确入口。

## UI 交付前清单

一次 UI 改动提交前逐项确认：

1. 能用一句话说明本次改动服务的真实工作流。
2. 四个一级 tab 的职责没有被稀释，没有新增二级 tab。
3. 新增或受影响的隐式状态都有显式控件和当前值。
4. 明暗模式在自动、浅色、深色下分别可用；用户显式选择刷新后保持。
5. 空状态、加载中、失败、待人工、禁用、完成状态都有设计。
6. 键盘能完成主路径；焦点可见且顺序正确。
7. 颜色对比达标，状态不是只靠颜色区分。
8. 390px 与 1440px 无溢出、重叠、遮挡。
9. 文案清楚、具体、可行动；不添加解释系统功能的占位说明。
10. 运行 `npm run test:chain`，并做四个大类 tab 的桌面和 390px 视觉检查；涉及主题时增加明暗双主题检查。

## 样式边界

成品样式只维护 `web/src/styles/tokens.css` 与 `web/src/styles/app.css`。旧 `app/styles.css` 已删除，不得恢复第二套样式源；任何视觉调整仍以上述交付前清单作为回归标准。
